# PureSupp - Мобильное приложение для проверки чистоты и реального состава БАДов
**Бизнес-модель:** B2C
## Elevator Pitch
Многие люди принимают БАДы, не подозревая, что в них могут содержаться тяжелые металлы или примеси, а реальное содержание активного вещества часто ниже заявленного. PureSupp — это мобильный сервис, который позволяет покупателю отсканировать штрих-код продукта и мгновенно получить отчет о его реальной чистоте и безопасности на основе независимых лабораторных данных. Мы помогаем осознанным потребителям выбирать только проверенные добавки, экономя их деньги и сохраняя здоровье.

## Роли и User Stories
Мы выделим три основные роли: Пользователь (Покупатель БАДов), Администратор контента и Сотрудник поддержки.
Для приоритезации используем фреймворк RICE:
 - **Reach** (Охват): 1 — мало, 2 — среднее, 3 — почти все.
 - **Impact** (Влияние): 1 — слабый эффект, 2 — заметный, 3 — супер заметно.
 - **Confidence** (Уверенность): 1 — просто идея, 2 — есть данные, 3 — железно уверены.
 - **Effort** (Затраты): 1 — пара дней, 2 — спринт, 3 — квартал.
 - **Score** = (Reach * Impact * Confidence) / Effort.

## MVP vs MLP
Разделим функционал на критически важный (скелет) и приносящий удовольствие пользователю (вау-эффект).
| **MVP (Minimum Viable Product)** | **MLP (Minimum Lovable Product)** |
|:---|:---|
| Сканирование штрих-кода. | Тёмная тема и премиальный UI. |
| База данных с рейтингом (Опасно/Безопасно). | Геймификация (ачивки за "чистую корзину"). |
| Поиск по названию. | Сравнение товаров по хим. составу. |
| Покупка подписки (Paywall). | Индивидуальные рекомендации по биохакингу. |
| Админка для загрузки результатов тестов. | Уведомления об отзыве партий товара. |

## Детализация требований для ключевых историй
Я выбрал две самые важные истории из MVP: Сканирование штрих-кода и Покупка подписки.

### История 1: «Сканирование штрих-кода и получение рейтинга»
#### Функциональные требования (ФТ):
1. Система должна запрашивать доступ к камере устройства при первом нажатии на иконку сканера.
2. Система должна распознавать форматы штрих-кодов EAN-13 и UPC-A.
3. При успешном распознавании система должна искать товар в БД и открывать карточку с цветовым индикатором (Зеленый/Желтый/Красный).
4. Если штрих-код не найден, система должна выводить алерт с предложением "Оставить заявку на проверку".

#### Нефункциональные требования (НФТ):
1. Время от распознавания штрих-кода до вывода результата на экран не должно превышать 1.5 секунды.
2. Сканер должен стабильно работать при уровне освещенности от 50 люкс.
3. Интерфейс карточки товара должен корректно отображаться на экранах от 4.7 до 6.7 дюймов.

### История 2: «Покупка платной подписки»
#### Функциональные требования (ФТ):
1. При нажатии на кнопку "Подробнее" в заблокированном блоке анализов система должна открывать системный боттомшит (шторку) с вариантами подписки.
2. Система должна предлагать 3 периода: Месяц, Полгода, Год.
3. После успешной оплаты через платежный шлюз статус пользователя в БД должен меняться на Premium мгновенно.
4. Система должна отправлять электронный чек на почту пользователя после транзакции.

#### Нефункциональные требования (НФТ):
1. Безопасность: Все платежные данные должны обрабатываться по стандарту PCI DSS, приложение не должно хранить данные карт на своей стороне.
2. Надежность: Сервер обработки платежей должен иметь аптайм 99.9%.
3. Удобство: Процесс оплаты (от клика до подтверждения) должен занимать не более 4 шагов.
